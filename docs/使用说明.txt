============================================================
  mirom 1.0.0  —  小米 ROM 极速下载器
  by poposjj
============================================================

【这是什么】
  专门用来从小米 CDN 下载 ROM 的工具。小米有 5 个下载节点
 (cdnorg / aliyun / bn / bigota / hugeota)，其中 bigota 和
  hugeota 会返回假的 206 响应 —— 看着像能下，实际传 256KB 就
  永久挂死。本工具会自动识别并跳过这类节点，只从真正能跑的
  节点上多连接抢带宽。

  实测：千兆网下 8 个 ROM 跑到 103~109 MB/s（千兆理论上限
  约 117 MB/s），并全部通过 MD5 校验。


【怎么用】
  1. 双击 mirom.exe
  2. 把小米 ROM 下载链接粘到最上面的输入框
     （形如 https://bigota.d.miui.com/.../xxx.zip）
  3. 点「开始下载」

  首次使用建议先点「仅测速」：它只探测节点速度、不写文件，
  让你先看看当前网络下哪条线路最快。

  下载中的文件放在： C:\Users\<你的用户名>\Downloads\Roms
  可以在界面上改输出目录。


【界面说明】
  · 顶部彩色标签：每个节点的实时状态
      绿 = 首选（最快最稳）
      橙 = 较快（速度可以但抖动大）
      灰 = 已被限速到不可用（已自动排除）
    如果看到「已自动跳过 N 个劣质节点」，说明保护生效了。

  · 中间折线图：实时速度曲线
      蓝线 = 总速度   青线 = 单条线路速度   虚线 = 均值
      线上的黄标是事件记录（并发数变化、线路增减等）
      右上角可切 30秒 / 60秒 / 2分钟 / 全程 视图

  · 阶段条：探测节点 → 并发调优 → 下载 → 完整性校验
      「并发调优」是自动寻找最佳并发连接数的过程，
      不是出错，等它跑完就进入下载。

  · 暂停 / 取消：
      暂停有约 4~5% 的粒度（已经在传的分片要写完才停），
      这是为了保证续传不出洞，属于正常现象。
      取消：探测/调优阶段数秒内停；下载阶段约 6 秒；
            校验阶段不可中断，跑完即停。


【设置（Ctrl+, 或菜单 设置 → 下载设置…）】
  以前这些参数只能在命令行敲，现在界面上就能改，改完自动记住：

    下载目录        下载的文件放哪儿
    并发连接数      0 = 自动调优（推荐）。手填会跳过并发爬坡。
    自动调优上限    自动调优时允许的最大连接数（默认 256）
    限速            0 = 不限速。限的是【总带宽】，所有连接共享。
    HTTP 代理       留空不用。例 http://127.0.0.1:7890
    多线路聚合      把多条 CDN 线路的带宽加起来，通常更快
    完成后校验MD5   强烈建议保持勾选，这是文件没坏的唯一保证
    预分配磁盘空间  避免边下边碎片化，机械盘建议勾选
    每次重新调优    默认复用 24 小时内的测速结果；勾上就每次重测
    跳过证书校验    只有公司中间人代理环境才需要

  设置存在 C:\Users\<你的用户名>\.mirom_gui.json，删掉即恢复默认。


【断点续传】
  中途关掉软件再打开，重新点「开始下载」会自动接着下。
  进度记录存在同目录的 <文件名>.mirom.json 里。
  ⚠ 别删数据文件只留 .mirom.json（反之亦然），
    工具检测到不匹配会重新下载。
  ✅ 下载完成并校验通过后，断点文件会被自动删除 —— 这是正常的。
     下次再下同一个文件会直接秒过（校验通过就不重复下载）。


【如果下载目录里已经有同名文件】
  点「开始下载」时会先弹窗问你，不会默默跳过：

    下载副本   保留原文件，另存为「xxx (1).zip」后照常下载
               （(1) 被占了会自动用 (2)、(3)…，绝不覆盖任何文件）
    覆盖重下   删掉旧的重新下一份，完成后照常校验
    跳过       不下载，只校验现有文件；通过就算完成
    取消       什么都不做

  ⚠ 如果那个文件带有 .mirom.json 断点文件，说明是「上次没下完」，
    这时不会弹窗，直接续传 —— 这是对的，不用管。


【工具菜单】
  · 运行引擎自检
      跑完会弹出一个结果窗口（确定 / 取消），同时把【完整】的逐项
      结果写进运行日志。以前只写日志最后 6 行，经常什么都看不到。

  · 导出本次测试数据 CSV
      仅测速之后就能导出，不必先下载完。导出内容：
        ① 节点探测表 —— 每个节点的 TTFB、服务器、是否可用、
                        被限速节点的实测速率
        ② 单连接基准表 —— 识别"是不是单连接限速"
        ③ 并发爬坡表 —— 每一档连接数的吞吐与抖动，拐点一目了然
        ④ 下载实时速度（有下载才有这一份）
        ⑤ 关键事件（换线、重排等发生在第几秒）

  · 诊断报告
      把环境信息 + 完整自检结果存成 mirom_diag.txt 放在下载目录，
      遇到问题直接把这个文件发出来即可。


【快捷方式 / 开机自启】（设置菜单里）
  · 创建桌面快捷方式
      在桌面建一个带正确图标的快捷方式。以后直接双击桌面图标就能用。
  · 开机自动启动
      勾选后每次开机自动启动 mirom（默认关闭）。
      再点一次即取消。
      这个勾选状态读的是系统里的真实情况 —— 就算你手动去
      「启动」文件夹删掉了快捷方式，菜单也会自动显示为未勾选。


【图标】
  程序、任务栏、窗口、桌面快捷方式、开机启动项用的都是同一个图标
  （橙色小米 mi 标）。图标由 assets\logo_src.webp 自动生成：
      python make_logo.py
  会产出多分辨率 logo.ico（16/24/32/48/64/128/256），Windows 会按
  场合自动挑最合适的一档 —— 所以任务栏小图标不会糊。
  打包时用 --icon 把图标写进 EXE，再 --add-data 把 assets 一起带上。


【常见问题】
  Q: 速度忽上忽下？
  A: CDN 本身波动就有 2 倍差距，同样的代码同一个文件，
     测出来可能是 1分39秒 也可能是 3分19秒。工具会自动
     调整并发数并切换线路，看「平均速度」看瞬时值靠谱。

  Q: 卡在 0% 不动？
  A: 大概率是你手动指定了 bigota / hugeota 这类节点。
     删掉链接重开，让它自动选路。

  Q: 进度条到 100% 了但还没结束？
  A: 进度是按「真正落盘、可续传的单元」算的，不会虚高。
     到 100% 后如果还在跑，那是在做最后的完整性校验 ——
     这一步要把整个文件读一遍算 MD5，大文件要几秒到十几秒。

  Q: 报「完整性校验失败」？
  A: 文件在传输中损坏了。直接重跑同一条命令即可 ——
     工具会检测到校验不通过并自动重新下载整份文件。

  Q: 点按钮的时候闪过一个黑框？
  A: 那是旧版本的问题。工具需要问系统"你这是固态还是机械盘"，
     旧版会起一个 PowerShell 窗口（冻结的 EXE 没有控制台，
     Windows 就给子进程新开一个）。现在已隐藏，并且同一个盘
     只问一次。如果还能看到，请把诊断报告发给我们。

  Q: 提示「输出路径过长」？
  A: Windows 默认路径上限 260 字符。把下载目录换浅一点，
     例如 D:\Roms。

  Q: 杀毒软件报警？
  A: 这是 PyInstaller 打包的 Python 程序常见的误报，
     源码完全公开，可自行审查。


【命令行（可选）】
  mirom.exe                       正常启动图形界面
  mirom.exe --diag 报告.txt       导出一份环境+自检报告（反馈问题时用）
  mirom.exe --desktop 2           启动后自动移到第 2 个虚拟桌面
  mirom.exe --shot 图.png         无窗口渲染一张界面截图（自动化用）

  引擎也可以脱离界面单独跑（需要 Python 环境）：
  python mirom.py --selftest      跑自检（约 10 秒，全部通过才算健康）
  python mirom.py <链接>          命令行下载
  python mirom.py <链接> --probe  只测速，不写任何文件

  调试用环境变量：
  MIROM_DEBUG_ACCT=1              每 3 秒打印一次进度记账体检
                                  （进度用位图算，位图按 1MB 单元增量标记，
                                    虚高应稳定在几十 MB；若涨到几百 MB 说明有 bug）


【关于取消】
  点「取消」后：
    · 探测/调优阶段：数秒内退出（这两个阶段还没有下载器，靠线程级取消标志）
    · 下载阶段：约 6 秒收尾（等各连接把手头那次读写完）
    · 校验阶段：不可中断，跑完即停
  取消会保留断点，重新点「开始下载」自动补下缺失分片。


【环境要求】
  Windows 10 / 11 64 位。免安装，解压即用。
  整个文件夹必须一起拷贝，不能只拷 mirom.exe
 （同级 _internal 目录里有运行库）。
